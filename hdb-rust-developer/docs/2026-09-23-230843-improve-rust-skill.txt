  What changed for each of your criteria:
  - Fast binaries: the release profile now uses opt-level = 3 instead of "z",
    which optimized for size. "z" is kept only for WASM and embedded targets.
    There's also a "measure before and after" step using hyperfine, criterion
    and flamegraph.
  - Minimal unwrap(): a [lints.clippy] block (unwrap_used, expect_used,
    indexing_slicing, pedantic) plus a clippy.toml that exempts tests. I tested
    it on a throwaway crate: main gets flagged and test code doesn't. There's
    also a table of safe replacements, covering indexing, byte slicing, overflow
    and as casts, which can panic or silently corrupt data.
  - Error handling: .context() on every ? that crosses file access, parsing or a
    subprocess. Keep the underlying error rather than converting it to a
    string, and show users Display output, not {:?}.
  - Type system: newtypes for IDs, "parse, don't validate", enums instead of
    combinations of flags, no _ => arm when matching on your own enums.
  - Ownership: an order to try things in: borrow, then move, clone once, Arc,
    and finally Arc<Mutex>. Plus std::thread::scope, and taking &[T], &Path or
    impl AsRef<Path> as arguments.
  - Memory: iterate instead of collecting into a Vec, with_capacity, mem::take,
    Arc<str>.
  - Simplicity: write the concrete version first. The one allowed exception is a
    trait at an I/O boundary that exists so tests can swap in a fake (like
    CommandRunner in channel-atlas).
  - Cohesive components: modules organized by domain, private by default, I/O
    kept at the edges, tempfile for tests that touch the file system.
  - Idiomatic / best practice: clippy now runs as --all-targets -- -D warnings,
    and Phase 1 has a new "design the types first" step.
